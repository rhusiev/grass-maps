# T-0314 emulator evidence

Device: `sdk_phone64_x86_64`, Android 15 (API 35), serial `emulator-5580`.
App: the debug build, application id `nl.r1a.grassmap`, `targetSdkVersion=36`.
Captured 2026-11-11 between 14:04 and 14:09 (emulator clock).

The route is `test-data/navigation/nav-route.json`, passed to the control
channel as `{"route": <the file>, "profile": "walk"}`. The debug build replays
`test-data/location/mock-walk.gpx` by default; the location-lifecycle section
uses the real platform source, selected with
`--ez t0103_platform_location true` as in `test-data/location/README.md`.

## 1. A location foreground service while guidance runs

```
$ tools/control/grassctl.py --serial emulator-5580 invoke core.nav.start '<route JSON>'
started=true phase=Following points=70 distance_m=382.587 profile=Walk

$ adb -s emulator-5580 shell dumpsys activity services nl.r1a.grassmap
  * ServiceRecord{c723f26 u0 nl.r1a.grassmap/.app.NavigationService c:nl.r1a.grassmap}
    intent={act=nl.r1a.grassmap.action.NAVIGATION_START cmp=nl.r1a.grassmap/.app.NavigationService}
    packageName=nl.r1a.grassmap
    targetSdkVersion=36
    startForegroundCount=1
    isForeground=true foregroundId=1 types=0x00000008 foregroundNoti=Notification(channel=navigation shortcut=null contentView=null vibrate=null sound=null defaults=0 flags=ONGOING_EVENT|ONLY_ALERT_ONCE|NO_CLEAR|FOREGROUND_SERVICE color=0x00000000 category=navigation actions=2 vis=PUBLIC)
```

`types=0x00000008` is `FOREGROUND_SERVICE_TYPE_LOCATION`. A second start while
the session runs does not create a second service or route:

```
$ ... invoke core.nav.start '<route JSON>'
started=false phase=Following points=70 distance_m=382.587 profile=Walk
```

```
$ adb -s emulator-5580 shell input keyevent KEYCODE_HOME
$ adb -s emulator-5580 shell dumpsys activity services nl.r1a.grassmap
    isForeground=true foregroundId=1 types=0x00000008 ...

14:08:22.431 I GrassMapsNavService: navigation-notification ... text="79 m"
14:08:23.429 I GrassMapsNavService: navigation-notification ... text="77 m"
14:08:24.430 I GrassMapsNavService: navigation-notification ... text="76 m"
```

With the platform source active, the GPS request stays active after Home:

```
    gps provider:
      service: ProviderRequest[@+1s0ms, HIGH_ACCURACY, WorkSource{10153 nl.r1a.grassmap}]
      listeners:
        10153/nl.r1a.grassmap/35ED41F8 Request[@+1s0ms HIGH_ACCURACY, WorkSource{10153 nl.r1a.grassmap}]

```

## 5. Leaving the app without navigation releases location

The app was launched with `--ez t0103_platform_location true` and no
navigation. While visible:

```
    gps provider:
      service: ProviderRequest[@+1s0ms, HIGH_ACCURACY, WorkSource{10153 nl.r1a.grassmap}]
      listeners:
        10153/nl.r1a.grassmap/9F7B3EA0 Request[@+1s0ms HIGH_ACCURACY, WorkSource{10153 nl.r1a.grassmap}]
        10153/nl.r1a.grassmap/35ED41F8 Request[@+1s0ms HIGH_ACCURACY, WorkSource{10153 nl.r1a.grassmap}]
```

After Home:

```
$ adb -s emulator-5580 shell input keyevent KEYCODE_HOME
    gps provider:
      service: ProviderRequest[OFF]
      listeners:
        10153/nl.r1a.grassmap/35ED41F8 {bg, na} Request[@+30m0s0ms HIGH_ACCURACY, minUpdateInterval=+1s0ms, WorkSource{10153 nl.r1a.grassmap}] (inactive)
```

The request is off and the remaining registration is marked `{bg, na}` and
`(inactive)`: the system delivers no fix to it. The history in the same dump
has no delivery after Home. The registration belongs to a plugin stream that
reads the raw location service rather than the shared source; it is outside the
navigation path and the system disables it with the app in the background. The
map collector's own registration (`9F7B3EA0`) was removed at Home.

## 6. Edge cases

Navigation ending while paused:

```
$ ... invoke core.nav.pause
changed=true phase=Paused paused=true
$ ... invoke core.nav.stop
stopped=true phase=Paused
$ adb -s emulator-5580 shell dumpsys activity services nl.r1a.grassmap
  (nothing)
$ adb -s emulator-5580 shell dumpsys notification --noredact | grep -c pkg=nl.r1a.grassmap
0
14:09:34.730 I GrassMapsNavigation: navigation-cancelled
14:09:34.733 I GrassMapsNavigation: navigation-service-stop phase=Stopped
```

The permission revoked mid-navigation (the system kills the process):

```
before: pid=2377, dumpsys activity services ... isForeground=true (1 record)
$ adb -s emulator-5580 shell pm revoke nl.r1a.grassmap android.permission.ACCESS_FINE_LOCATION
after:  pid empty
        dumpsys activity services nl.r1a.grassmap: (nothing)
        dumpsys notification --noredact | grep -c pkg=nl.r1a.grassmap: 0
```

The service is `START_NOT_STICKY`, so the process death is not followed by a
restart without a route.
